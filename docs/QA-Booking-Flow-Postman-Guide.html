TravelVIP B2B — QA Booking Flow Guide

For QA team · Hotel · Flight · Cab · Postman
Staging: https://api-staging.travelvip.ai
Collection: TravelVIP-Dynamic-Flights-Hotels.postman_collection.json

Setup (do once)

  1. Import Postman collection + B2B Dev environment
  2. Set: base_url, partner_id, partner_secret, signing_key, tier_id
  3. Run Auth: Partner Token → User Session
  4. Keep one correlation_id for the whole flow
HeaderValueWhen
AuthorizationBearer {{auth_token}}All APIs
X-Partner-Key{{access_token}}Hotel finalize · Flight issue-ticket · Cab finalize
X-Correlation-ID{{correlation_id}}All APIs (same ID)
Cheat sheet:
HOTEL: details.requestId + bookingCode → prebook → finalize → status(BR)
FLIGHT: search.searchId → pricing → issue-ticket → status(BR)
CAB: search.searchId → fare → finalize → status(BR)

HOTEL Booking Flow

Auth → Search → Details → Prebook → Finalize → Status

Step 1 — Search

POST /v1/hotels/search · Query: pid=vgm

Send in bodyExample
checkin / checkout2026-09-23 / 2026-09-24
entityId39627872 (Hilltop Mumbai)
nationalityIN
typeHOTEL
rooms1 adult

Copy forward: same dates + entity + rooms → Details & Finalize

Step 2 — Details

POST /v1/hotels/details · Same body as Search without type

From responseCopy to
requestIdPrebook + Finalize
results[0].rooms[0].bookingCodePrebook + Finalize
Use Details requestId — not Search requestId.

Step 3 — Prebook

POST /v1/hotels/prebook

{ "bookingCode": "<Details>", "requestId": "<Details>" }
From responseCopy to
bookingContextFinalize

Step 4 — Finalize (BOOK)

POST /v1/hotels/finalize-booking · Needs X-Partner-Key

FieldSource
bookingContextPrebook
bookingCode, requestIdDetails
checkin, checkout, rooms, contactYour test data + PAN if mandatory

After book: save bookingRefId → GET status

Step 5 — Status

GET /v1/hotels/bookings/{bookingRefId}/status — poll until Confirmed / Failed / Inprogress

FLIGHT Booking Flow

Auth → Search (poll) → Details → Pricing → Issue-ticket → Status

Step 1 — Search

POST /v1/flights/search

SendExample
itineraryDEL → BOM, date YYYY-MM-DD
journeyTypeONE_WAY
travellers1 adult
cabinClassECONOMY

Copy forward: results[ONWARD].options[0].searchId → all next steps

Round trip: copy two searchIds (ONWARD + RETURN).

Step 2 — Details

{ "journeyType": "ONE_WAY", "selection": { "selectedSearchIds": ["<searchId>"] } }

Step 3 — Pricing

Same body as Details.

From responseCopy to
priceIdIssue-ticket → data.priceId
bookingContextIssue-ticket → bookingReference

Step 4 — Issue ticket (BOOK)

POST /api/v2/flights/booking/issue-ticket · Needs X-Partner-Key

Issue-ticket fieldSource
bookingReferencepricing.bookingContext
searchIds[]search searchId
data.priceIdpricing.priceId
data.passengers[], contactYour test pax data
Field is named bookingReference but value = pricing.bookingContext

Step 5 — Status

GET /v1/flights/booking/{bookingReference}/status

Issue-ticket books a LIVE ticket on staging. Run only when needed.

CAB Booking Flow

Auth → Search → Fare → Finalize → Status

Copy forward: pick RECOMMENDED cab → cabs[].searchId

Step 2 — Fare

{ "searchId": "<from Cab Search>" }

bookingReferenceFinalize
priceIdFinalize

Step 3 — Finalize (BOOK)

FieldSource
bookingReference, priceIdFare

Step 4 — Status

QA reminders

  • Run requests top to bottom in Postman — scripts auto-save variables
  • Never reuse expired requestId / bookingCode / priceId
  • Do not commit secrets (partner_secret, signing_key)
  • Hotel/Flight/Cab finalize = live booking on staging
